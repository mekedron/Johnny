## Codebase Patterns (Study These First)

- **Frontend layout owns `<main>`**: `frontend/src/routes/+layout.svelte` wraps `{@render children()}` in `<main class="content">`. Route pages MUST NOT render their own `<main>` element (invalid nested landmarks). Use `<section>`, `<div>`, or just bare elements inside route `+page.svelte` files.
- **Active-route detection**: Use `import { page } from '$app/state'` (Svelte 5 runes API in SvelteKit 2.16+). Compare `page.url.pathname` with `href`. Apply both a class (`class:active`) and `aria-current="page"` for a11y.
- **Browser verification fallback**: `.mcp.json` declares `chrome-devtools-mcp` for future sessions, but MCPs load at session start so they can't be used in the same iteration they're added. For one-shot verification, `npx playwright` works: `npm install playwright` in `/tmp`, then `npx playwright install chromium`, then a small `.mjs` script that captures screenshots to `.ralph-tui/reports/`.
- **Frontend quality gates**: `pnpm typecheck` runs `svelte-kit sync && svelte-check`; `pnpm lint` runs ESLint. Both must be invoked from `frontend/`.
- **Backend quality gates**: `uv run pytest`, `uv run ruff check`, `uv run mypy` from `backend/`.
- **DB layer location**: SQLAlchemy 2.0 models live in `backend/app/db/models.py`; declarative `Base` in `backend/app/db/base.py`; engine + `SessionLocal` + `session_scope()` context manager in `backend/app/db/session.py`. `app.config.get_settings()` reads `DATABASE_URL` from env (default points at compose `postgres`). All public models re-exported from `app.db.__init__`.
- **Portable enum + JSON columns**: For tests without PostgreSQL, use `SAEnum(..., native_enum=False, length=N)` (renders as `VARCHAR + CHECK`) and `_json_column()` helper in `app/db/models.py` (`JSON().with_variant(JSONB(), "postgresql")`). - **Selfcheck pattern**: `python -m johnny.meet_worker.selfcheck` shells out to `pactl list short sinks/sources` (tab-separated; column 1 is the name) and verifies the expected names are present. - **Audio bridge — parec/pacat over subprocess.PIPE**: `MeetAudioBridge` (`johnny/meet_worker/audio_bridge.py`) shells out to `parec --device=<sink>.monitor --rate=16000 --channels=1 --format=s16le --raw` for capture and `pacat --playback --device=<source>_loopback ...` for playback. Subprocess stdout/stdin are read/written via `loop.run_in_executor(None, fn, ...)` so the asyncio loop never blocks on the OS pipe. No external Python deps — keeps the meet-worker image free of numpy/scipy/audioop (latter is removed in 3.13).
- **Bounded asyncio queue with EOS sentinel + slot reserve**: For real-time capture, `asyncio.Queue(maxsize=N+1)` lets the producer always have room for a trailing `None` sentinel that signals EOF to the async-generator consumer. While streaming, the pump drops the oldest frame whenever `qsize() >= N` to keep latency bounded; on EOF, `put_nowait(None)` is wrapped in `suppress(QueueFull)` for defensive paranoia. Without the +1 reserve, the sentinel push would block forever when the queue is at user-facing capacity.
- **Resampling without numpy**: `resample_pcm16(pcm, src, dst)` uses `array.array("h")` + linear interpolation in pure Python. Adequate for sub-second 8k/16k/24k/48k voice chunks; not anti-aliased, so aggressive downsampling will alias HF content. For test correctness: a constant signal must round-trip exactly (`all(s == 1000)`); a 440 Hz sine at 48 kHz → 16 kHz preserves peak amplitude within ~10%; ramp signal preserves endpoints exactly.
- **Protocol-typed subprocess for testable I/O**: Defining a `_Process` `typing.Protocol` (`stdout: IO[bytes] | None`, `stdin: IO[bytes] | None`, `poll/terminate/kill/wait`) lets `subprocess.Popen[bytes]` satisfy the same shape as a `_FakeProcess` wrapping `io.BytesIO`. Override `_spawn_capture_process` / `_spawn_playback_process` in a `_FakeBridge` subclass to inject the fakes in tests — no `unittest.mock.patch` ceremony. Note: protocol-Attribute types are invariant in mypy strict — type the fake's `stdin: IO[bytes] | None` (not `_FakeStdin | None`) and `isinstance`-narrow in tests that need the subtype.
- **Provider ABCs — async generators declared on sync `def`**: Streaming ABC methods like `STTProvider.transcribe_stream` and `TTSProvider.synthesize_stream` are declared as `@abstractmethod def foo(...) -> AsyncIterator[T]: ...` (NOT `async def`). The signature returns `AsyncIterator[T]`; the implementor writes `async def foo(...)` with `yield` statements — the language transforms the body into an async-generator that *is* an `AsyncIterator[T]`. Declaring the base as `async def` would mark it a coroutine, not an iterator factory, and confuses both mypy and runtime semantics. `LLMProvider.chat`, by contrast, is `async def` because it returns a single coroutine resolving to `LLMResponse`.
- **`ruff B027` for intentional non-abstract ABC hooks**: When you want an empty default implementation in an ABC (e.g., `async def close(self) -> None:` as a hook subclasses *may* override), ruff flags it as B027 ("forgot @abstractmethod?"). Suppress with `# noqa: B027 — intentional non-abstract hook` rather than adding a `pass` (still empty) or making it abstract (forces every stateless adapter to write boilerplate).

SQLAlchemy's `Model.__table__` is typed as `FromClause` in stubs but is `Table` at runtime — needs `# type: ignore[list-item]` on the `tables=[...]` arg under mypy strict. Pattern keeps DB-touching tests fast and dialect-portable.

- **Subprocess-driven TTS adapter pattern**: Local TTS via the `piper` binary follows the same `_Process` Protocol + override-`_spawn_process` testing pattern as `MeetAudioBridge`. A `carry` buffer holds any 1-byte tail across chunk reads so `_resample_pcm16` always sees an even-length input. `try/finally` around the `yield` loop ensures `_cleanup` (terminate + wait + kill-on-timeout) runs even when the consumer breaks early or `aclose()`s the generator.

- **`AsyncIterator[T]` return type lacks `aclose`**: `TTSProvider.synthesize_stream` is declared returning `AsyncIterator[bytes]` (per the ABC), but the implementation is an async generator. To call `.aclose()` from a test, cast the return value: `agen = cast(AsyncGenerator[bytes, None], adapter.synthesize_stream("hi"))` — mypy will reject `agen.aclose()` on the narrower `AsyncIterator` type. - **httpx `MockTransport` for streaming-response adapter tests**: `httpx.MockTransport(handler)` accepts a sync handler `Callable[[Request], Response]`. For streaming bodies, build the `Response` with `content=<async-iterator-factory>` — `httpx` accepts both bytes and iterators. - **Cloud TTS adapter shape (US-016 pattern)**: `__init__` validates config → eager `self._client = self._create_client()` so the client is reused across calls; `synthesize_stream(text, voice_id=None)` is an `async def` generator that calls `async with self._client.stream(...) as response:` and yields aligned S16 frames; `close()` calls `await self._client.aclose()` (suppress exceptions). Cancellation: when the consumer `aclose()`s the generator, `GeneratorExit` propagates through the `yield`, then through the `async with`, which closes the underlying response and connection — no manual cleanup needed.
- **Cloud TTS error mapping**: Wrap the `async with client.stream(...)` body in `try/except httpx.HTTPError`. Inside, call `_raise_for_status(response)` which `await response.aread()`s the (small) error body, tries to parse JSON for a `{"error": {"message": ...}}` (OpenAI) or `{"detail": {"message"}}` / `{"detail": "..."}` (ElevenLabs) shape, and raises `TTSError(f"...HTTP {status}: {detail}")`. The outer `except httpx.HTTPError` catches network/timeout errors and translates them into `TTSError("provider ... request failed: ...")`. The `if isinstance(exc, TTSError): raise` guard prevents double-wrapping when `_raise_for_status` already raised.
- **ElevenLabs `pcm_16000` output_format saves a resampling step**: ElevenLabs streams 16 kHz mono S16LE directly when `?output_format=pcm_16000` is set. No resampler needed, just carry-byte alignment. OpenAI's `response_format=pcm` is 24 kHz mono S16LE — needs resampling. Always check the provider's PCM output sample rate when wiring a new cloud TTS adapter.
- **Meet-worker image must `pip install httpx` when `app/providers/__init__.py` auto-registers cloud adapters**: Adding `openai_tts.py` / `elevenlabs_tts.py` to the auto-register block makes `import app.providers` pull in `httpx` at module level. The meet-worker copies `app/providers/` into its image, so the missing `httpx` would break `from app.providers import STTProvider` at runtime. Add `pip install --no-cache-dir httpx==X` to `Dockerfile.meet-worker` whenever an httpx-using adapter joins the auto-register set.
- **Single adapter for the entire OpenAI-compatible ecosystem**: vLLM, Ollama, LM Studio, llama.cpp's `server`, OpenRouter, Together all speak the same `/v1/chat/completions` schema. The `OpenAICompatibleLLM` adapter (registered name: `"openai-compatible"`) wraps all of them. Multiple `provider_credentials` rows can use the same adapter but with different `base_url` and `model` options. Naming convention: when a single adapter covers many backends, register it under a generic name (`"openai-compatible"`), NOT the most obvious one (`"openai"` is reserved for the dedicated cloud OpenAI adapter in US-014).
- **Tool-call argument shape varies across OpenAI-compatible servers**: OpenAI canonical: `function.arguments` is a JSON-encoded string. Ollama: it's a raw object. Handle both — `isinstance(args, dict)` first, then `json.loads(str(args))`. Missing `id` (Ollama omits it on the first tool call of a turn) defaults to empty string. Robust adapters NEVER assume the server emits exactly OpenAI's wire format.
- **Hermes-style tool calling pattern**: (1) inject `<tools>...</tools>` block + example `<tool_call>{json}</tool_call>` block into the system message (prepend a new system or extend the existing one — don't drop the user's system prompt). (2) Regex-extract `<tool_call>\s*(.+?)\s*</tool_call>` (DOTALL) from the assistant response content; each block becomes `ToolCall(id=f"call_{idx}", name=..., arguments=...)`. Server-set `finish_reason` is usually `"stop"` because Hermes models don't know about OpenAI's tool-calling protocol — promote it to `"tool_calls"` in the adapter when calls are found, so downstream code can branch the same way regardless of `tool_format`.
- **`opts.get("temperature", DEFAULT_TEMPERATURE)` instead of `opts.get("temperature") or DEFAULT_TEMPERATURE`**: the `or` shortcut silently overrides a configured `0.0` with the default. Always use `.get(key, default)` for numeric options where `0` is a meaningful value (temperature, top_p, seed). The `or` form is fine for required-truthy options like model names.
- **Shared LLM contract via `_llm_contract.py`**: mirror of `_tts_contract.py`. - Implemented `OpenAICompatibleLLM` adapter (`backend/app/providers/openai_compatible_llm.py`) — a single class that targets any endpoint implementing OpenAI's `/v1/chat/completions` schema. Covers vLLM, Ollama, LM Studio, llama.cpp's `server` binary, OpenRouter, Together, and most local LLM runtimes. The `base_url` + `model` options discriminate at runtime so the same adapter handles every flavour of OpenAI-compatible host.
- Configuration: `model` (required), `base_url` (required, trailing slash stripped), `tool_format` (`"openai"` default or `"hermes"`), `temperature` (default 0.7, 0.0 honored), `max_tokens` (default unset), `timeout_s` (default 60). Credentials: `api_key` (optional — sent as `Authorization: Bearer` when set; Ollama ignores, OpenRouter requires).
- Tool-call format negotiation:
  - **OpenAI-native** — tools serialized into the `tools` request field as `{type: "function", function: {name, description, parameters}}`; response `tool_calls[]` parsed into `ToolCall` objects. `function.arguments` accepted as either a JSON-encoded string (canonical OpenAI shape) or a raw object (Ollama shape). Missing `id` defaults to empty string for runtimes that omit it.
  - **Hermes-style** — tools injected into the system message (prepended or appended to existing system) using the `<tools>...</tools>` block + `<tool_call>...</tool_call>` example. Response content scanned with `re.compile(r"<tool_call>\s*(.+?)\s*</tool_call>", re.DOTALL)`; each block JSON-decoded into a `ToolCall(id=f"call_{idx}", ...)`. `finish_reason` promoted from `"stop"` → `"tool_calls"` when calls are present so callers can branch the same way as OpenAI-native.
- Structured output: when `response_format` is supplied, the adapter forwards it verbatim and attempts `json.loads(text)` on the response content. Successful parse → `LLMResponse.structured_output`; non-JSON content silently leaves `structured_output=None`.
- Error mapping: every failure surfaces as `LLMError` (the shared `ProviderError` hierarchy). HTTP errors include the provider's `error.message` / `error` (string) / `message` / raw-body[:200] detail. `httpx.HTTPError` → `LLMError("openai-compatible LLM request failed: ...")`. Malformed JSON / non-object response / missing `choices` / bad tool-call shape all raise `LLMError` with the offending detail.

  - **One adapter covers the entire OpenAI-compatible ecosystem.** vLLM, Ollama, LM Studio, llama.cpp, OpenRouter, and Together all speak the same `/v1/chat/completions` schema.   - **Tool-call argument shape varies across compatible servers.** OpenAI canonical: `function.arguments` is a JSON-encoded string. Ollama: it's a raw object. Handle both — try `isinstance(args, dict)` first, then fall back to `json.loads(str(args))`. Missing `id` field (Ollama omits it on the first tool call of a turn) defaults to empty string. (Promoted.)
  - **Hermes-style tool calling is two transformations**: (1) inject `<tools>...</tools>` + example `<tool_call>` block into the system message (prepend or merge with existing system content), (2) regex-extract `<tool_call>{json}</tool_call>` blocks from the assistant response content. (Promoted.)

The error-detail path in this adapter uses `.content` because we're on the non-streaming path; the cloud TTS adapters use `.aread()` because they're inside an `async with client.stream(...)` block.
