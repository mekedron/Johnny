## Codebase Patterns (Study These First)

- **Run pytest in the worker container** (not api): the api image is built from production-shape Dockerfile (`COPY . .`) and has no bind mount unless launched via `./run-dev.sh`. The `worker` service in dev mode bind-mounts `./backend` to `/workspace`, so host edits are visible immediately. The image's `/opt/venv` was built via `uv` and has no `pip`; install dev deps with `uv pip install --python /opt/venv/bin/python pytest pytest-asyncio aiosqlite ruff mypy types-PyYAML`, then run `docker compose exec -w /workspace worker python -m pytest …`.
- **`PipelineConfig` is `@dataclass(frozen=True, slots=True)`**: add fields with sensible defaults so existing call-sites keep working without modification. Document the *why* in a docstring directly under the field — the file is the canonical config reference for the whole pipeline.
- **Barge-in has two paths**: fast VAD-driven (Johnny-ze3, in `_utterances`) cuts TTS within ~200 ms of speech onset; slow classifier (Johnny-di9, in `_classify_barge_in_intent`) runs post-utterance as a fire-and-forget task spawned at `_transcribe_and_emit`. The slow path is observability + edge-cases, not the user-facing budget — fail-open is the right default when its LLM is slow.
- **STT silence hallucinations belong at the adapter, not the pipeline gate**: Whisper segments expose `no_speech_prob` — the model's own probability that the audio was silence. Filtering on that signal inside `app/providers/faster_whisper_stt.py` catches *novel* hallucinations ("Does Olam A.P.I.", Welsh nonsense) that a curated stoplist in `pipeline.py` can never anticipate. The pipeline's `DEFAULT_NOISE_STOPLIST` (Johnny-ckz.14) handles known patterns ("you", "thank you", filler tokens); the adapter's `no_speech_threshold` handles everything else. Defence in depth — keep both.
- **Provider adapters live in the api image, not just meet-worker**: the in-process `BrowserPipelineSpec` (`app/services/browser_pipeline_runner.py`) means `/playground` runs the FULL voice pipeline inside the api container — so any STT-adapter change has to land in BOTH images (api + meet-worker). The api image is COPY-baked (`Dockerfile`), so after editing `app/providers/*.py` run `docker compose build api && docker compose up -d api` before exercising the playground; the worker has a bind mount and picks up host edits live, but the api does not.
- **`provider_credentials.is_active` per kind is touched in only two places**: (1) `app/api/providers.py` — `activate_provider` (deactivates same-kind siblings then flips this row True), `deactivate_provider` (explicit user click), `create_provider` (always inserts inactive). `update_provider` does NOT touch `is_active` — schema-driven merges drop the field via `merged = {k: v for k, v in baseline.items() if schema.field(k) is not None}` because the schemas don't declare `is_active`. (2) `app/services/providers_seed.py` — only mutates when `JOHNNY_PROVIDERS_FILE` exists. Missing file = early return = no-op. INSERT_ONLY mode skips existing rows entirely so `is_active` is preserved across restart. OVERWRITE mode is the only path that intentionally clears the flag (when the file explicitly lists `is_active: false` for an existing identity, per the documented export→edit→import roundtrip). Symmetric across LLM/STT/TTS — no kind-specific branch anywhere.
- **`ProviderSchema.tips` is the in-UI knowledge-capture surface**: when you need to put operator know-how (latency rules of thumb, knob trade-offs, cost guidance) directly inside `/providers`, edit the adapter's `field_schema()` and pass `tips=(ProviderTip(topic=..., body=...), ...)`. The schema serialises tips automatically; the frontend renders them as a "Latency & tuning tips" section below the form fields. Topic is a short headline; body is 1-2 sentences with a concrete number where possible. Adapter file is the canonical home — don't fork knowledge into a separate docs file (it goes stale next to the knobs it's about). After editing, rebuild the api image (`docker compose build api && docker compose up -d api`) — the COPY-baked Dockerfile won't pick up the change otherwise.
- **`_utterance_count` is NOT a valid turn_id from inside the response loop**: transcription (`_transcribe_and_emit`) and response (`_respond_to_transcript`) run as concurrent tasks (Johnny-har). By the time the response loop dequeues transcript N and starts router/answer/tts, the transcribe loop may have incremented `_utterance_count` past N. For activity-log-style cross-stage correlation (Johnny-ckz.7), stamp `(turn_id, anchor_ms)` in a `dict[int, tuple[int, int]]` keyed by `id(transcript)` at STT-finalise time, then `pop()` it when the response loop dequeues. Falls back to `_utterance_count + now` for transcripts injected via `feed_text` (no transcribe-loop stamp). Same caveat applies to ANY new code that needs "what turn am I in?" from the response side — don't read `_utterance_count` there.
- **The pipeline event bus is multiplexed**: every new event TYPE shares one Redis pub/sub channel per session and one `InMemoryEventBus.snapshot()` in tests. When adding a new type (e.g. Johnny-ckz.7's `PipelineTiming`), the existing tests that assert `[e.type for e in bus.snapshot()] == [...]` will fail because the new events leak in. The repo convention: filter at the test site — `[e.type for e in bus.snapshot() if e.type != "<new_type>"]` — rather than gating the publish at the source. Observability events (timings, traces) should publish unconditionally so they show up in the activity log; only the assertion list needs updating.
- **The migrate sidecar image must be rebuilt alongside api+worker**: `docker-compose.yml` defines `api`, `worker`, and `migrate` as three separate services with three separate images, all built from the same `backend/Dockerfile`. `docker compose build api` only rebuilds the api image — migrate keeps its old layer with whichever migrations it had at last build. After adding a new alembic revision, run `docker compose build api migrate worker` (or `docker compose build` for all) so the migrate sidecar can find your new `0008_*.py` file at startup. Symptom of missing this: migrate fails with `Can't locate revision identified by 'NNNN'` even though the file exists on the host and the api image has it.
- **Cartesia TTS uses `POST /tts/bytes` with `container=raw, encoding=pcm_s16le, sample_rate=16000`**: the simplest of Cartesia's three streaming surfaces (WebSocket / SSE / raw HTTP). The chunked HTTP response body IS the PCM stream — no SSE framing, no WebSocket framing, no resampling. Mirrors the ElevenLabs pattern (`response.aiter_bytes` → carry-byte alignment → yield). Auth header is `X-API-Key: <key>` (Cartesia accepts both X-API-Key and Authorization: Bearer — X-API-Key is idiomatic in their docs). Mandatory `Cartesia-Version` header pinned to `2026-03-01` (current at 2026-06-07 fetch date); the API ships breaking changes between dated versions so this pin is load-bearing. Voice IDs are UUIDs from `GET /voices`; paginated via `starting_after` / `has_more`. Sonic 3.5 advertises sub-200 ms time-to-first-audio from US/EU — comparable to ElevenLabs Flash v2.5.
- **Dual-mode pipeline routing lives at BOTH session entry points (Johnny-ckz.17)**: the meet-worker reads `JOHNNY_PIPELINE_MODE` env var (default `split`) inside `johnny.meet_worker.pipeline_runner.build_and_run_pipeline`, while the in-process browser runner reads `BrowserPipelineSpec.pipeline_mode` inside `assemble_browser_pipeline`. Both delegate to either `VoicePipeline` (split: STT→LLM→TTS) or `UnifiedVoicePipeline` (unified: a single `S2SProvider`). The router lives inside the assembler — there's no codepath that constructs `VoicePipeline` directly without first checking the mode. Persistence is the singleton `pipeline_settings` table (id=1, default 'split') read once at session start by `resolve_pipeline_mode`. The `docker_launcher` forwards the persisted mode into the worker's env via `LaunchContext.pipeline_mode` so the meet-worker stays SQLAlchemy-free.
- **The unified pipeline's events loop blocks on `queue.get()` forever unless the session is closed**: `S2SSession.events()` is an async iterator that exits only when the queue receives a `None` sentinel from `close()`. The capture loop's finally calls `commit_user_turn`, which queues response events; the events loop drains them but then blocks on the next `get`. The fix in `UnifiedVoicePipeline.run` is a two-phase teardown: after the first wait (capture EOF or stop signal) gives a 500 ms drain window, then `await session.close()` (queues None), then a 1 s wait for the events loop to exit naturally on the sentinel, then cancel any stragglers. Without this, AgentSpoke + final transcripts get cancelled mid-flight when the run loop tears down.
- **`ProviderInstance` is `_ProviderBase` not a `A | B | C | D` union**: originally a `STTProvider | LLMProvider | TTSProvider` union, but Johnny-ckz.17 added a fourth ABC (`S2SProvider`) in a separate module to keep import isolation. PEP 604 forward refs (`"S2SProvider"`) don't work in runtime type unions — `TypeError: unsupported operand type(s) for |: 'types.UnionType' and 'str'`. The fix: alias `ProviderInstance = _ProviderBase`, which is the common supertype of every provider ABC. Runtime `isinstance(x, ProviderInstance)` still works correctly.
- **`ck_provider_credentials_kind` CHECK was missed in Johnny-ckz.17 (Johnny-ckz.21)**: the initial schema migration 0001 created `CHECK (kind IN ('stt', 'llm', 'tts'))`. Johnny-ckz.17 widened the Python `ProviderKind` enum to include `s2s` but the corresponding DB CHECK was overlooked because the model declares `native_enum=False` + no explicit `CheckConstraint`. Symptom: inserting an S2S row failed with an `IntegrityError`, which the `create_provider` API surfaced as a misleading "display name already exists" (the catch-all branch). Lesson for future kind widenings: grep the `versions/` tree for `_in_list("kind"` / similar CHECK helpers, not just the SQLAlchemy model.

- **Gemini Live model names diverge from marketing aliases (Johnny-ckz.20)**: the Google docs frequently surface a `gemini-live-2.5-flash-native-audio` alias, but the v1beta WebSocket endpoint only recognises the raw `gemini-2.5-flash-native-audio-*` form — sending the aliased name yields a 1008 policy violation ("models/... is not found for API version v1beta, or is not supported for bidiGenerateContent"). The authoritative list comes from `GET /v1beta/models?key=...&pageSize=200` filtered to entries with `bidiGenerateContent` in `supportedGenerationMethods` — at fetch date 2026-06-07 that yielded only `gemini-2.5-flash-native-audio-latest` (stable), `gemini-2.5-flash-native-audio-preview-09-2025` (legacy preview), `gemini-2.5-flash-native-audio-preview-12-2025` (preview), and `gemini-3.1-flash-live-preview` (newest). Encode the default as the `-latest` form and surface those four exact names in the dropdown — anything else fails at session open with a misleading error.
- **Gemini Live ignores sine-wave / silence input for turn detection (Johnny-ckz.20)**: with the default `automatic_activity_detection` enabled, the server's VAD is tuned for human voice — a 440 Hz tone won't fire turn detection and `audioStreamEnd: true` is treated as a stream signal not a turn boundary, so a silent / synthetic-tone test just hangs waiting for a response. The two paths that DO work: (a) send `clientContent` with text (not part of our `S2SSession` ABC, so unavailable to the unified pipeline), or (b) disable server VAD via `realtime_input_config.automatic_activity_detection.disabled=true` in setup and drive turns explicitly with `activityStart` / `activityEnd`. The adapter exposes a `disable_server_vad` option for (b), used in the live integration tests so they're deterministic without needing a real-speech WAV. Production users keep the default (server VAD) — it's more accurate for actual voice input than client-side activity markers.
- **Gemini Live has no client-side "cancel response" message (Johnny-ckz.20)**: unlike OpenAI Realtime which exposes `response.cancel`, Gemini Live's barge-in is entirely VAD-driven on the server. The way to interrupt mid-response is to send a NEW user turn — auto VAD picks up the speech, manual VAD reads `activityStart`, either way the server emits `serverContent.interrupted: true` and stops generation. The adapter's `session.interrupt()` sends `realtimeInput.activityEnd: {}` as a soft signal but the pipeline-side `UnifiedVoicePipeline.interrupt()` is what actually cancels playback (via `transport.cancel_playback`). Real-server confirmed: a fresh `send_audio` + `commit_user_turn` after the first audio frame triggers the interrupt path and a clean `S2SResponseCompleted` event arrives within seconds.
- **OpenAI Realtime GA reshape: `session.update` REQUIRES `rate` on BOTH input AND output audio.format (Johnny-ckz.19)**: the May 2026 GA reshape nested audio config under `session.audio.input` / `session.audio.output` and renamed `modalities` → `output_modalities`. The docs example often shows the output format as just `{"type": "audio/pcm"}` without a rate — that's incomplete. The live API rejects it with "Missing required parameter: 'session.audio.output.format.rate'" only after the session is opened (not at WS connect time). Both input and output formats need `{"type": "audio/pcm", "rate": 24000}`. The minimum sample rate is 24 kHz; the GA endpoint rejects 16 kHz with "integer below minimum value". The pipeline-side adapter upsamples capture (16 → 24 kHz) and downsamples assistant audio (24 → 16 kHz) at the wire boundary so the rest of the pipeline stays at one rate.
- **OpenAI Realtime: model name pins to `gpt-realtime-2` (May 2026 GA flagship)** — siblings `gpt-realtime-mini` (cheaper), `gpt-realtime` (Aug 2025 GA, legacy). `gpt-4o-realtime-preview-2024-12-17` is DEPRECATED and rejects the GA session shape because it requires the flat pre-GA keys. Two new flagship voices are Realtime-exclusive: `marin` (warm/natural) and `cedar` (deeper/authoritative); the legacy 4o-realtime voices (alloy/ash/ballad/coral/echo/sage/shimmer/verse) still work. **`OpenAI-Beta: realtime=v1` header is REMOVED in GA** — sending it routes to the deprecated beta endpoint and gets rejected with "The Realtime Beta API is no longer supported". Authentication is just `Authorization: Bearer <api_key>`. Sessions cap at 30 min (`error.code=session_expired`); long meetings need a reconnect strategy not implemented yet.
- **OpenAI Realtime exposes a real client-side `response.cancel` for barge-in (Johnny-ckz.19)** — unlike Gemini Live which is VAD-only. The adapter's `interrupt()` sends BOTH `response.cancel` (stops generation) AND `input_audio_buffer.clear` (drops pending uncommitted user audio so the next turn starts clean). Server then emits `response.done` with `status: "cancelled"`, which the adapter maps to `finish_reason="interrupted"`. Server VAD path is also available: `input_audio_buffer.speech_started` arrives within ~200 ms of fresh user voice and the adapter eagerly emits an interrupted marker so the pipeline doesn't wait for the eventual `response.done(cancelled)` — that lets the in-flight assistant audio persist with the right finish_reason and stops new frame accumulation.
- **OpenAI Realtime API requires ≥100 ms of audio in the buffer before commit (Johnny-ckz.19)** — sending pure silence (all-zero PCM) followed by `input_audio_buffer.commit` yields "Error committing input audio buffer: buffer too small. Expected at least 100ms of audio, but buffer only has 0.00ms of audio." Live integration tests use a 1 s 440 Hz sine tone with `turn_detection="none"` so the buffer crosses the gate and the test drives the turn deterministically without depending on server VAD detecting speech in synthetic audio. Production users keep server_vad on — fine for real voice input.
- **Gemini Live treats every post-commit audio chunk as a NEW user activity (Johnny-ckz.22)** — in manual-VAD mode (`disable_server_vad=True`) the adapter sends `activityStart` on the first `send_audio` after every `activityEnd`. So if a harness keeps feeding silence frames to the session AFTER `commit_user_turn`, each frame opens a fresh activity and the server interprets that as a barge-in, cancelling the in-flight response. The unified-pipeline harness handles this by having its holding transport switch to yielding `b""` after the commit driver fires; the pipeline's `if not frame: continue` drops empty frames so they never reach `send_audio`. Capture stays alive (no EOF, no teardown) without re-feeding audio. Don't apply this transformation to OpenAI Realtime — it accepts post-commit audio as buffering for the next turn without re-firing.
- **`UnifiedVoicePipeline._capture_loop` only commits on capture EOF, never mid-stream (Johnny-ckz.22)** — when the harness wants to drive a deterministic turn against an S2S provider, it can't just feed audio and wait for the response: the pipeline calls `commit_user_turn` ONLY in the `finally` of its capture loop, after the capture iterator exits. To exercise an S2S session against a finite scripted timeline, the harness needs (a) a commit driver that calls `session.commit_user_turn()` from a side-task after the speaker's last speech event finishes + a small grace period, AND (b) a holding transport that keeps capture alive (yielding empty frames so the pipeline's drop-on-empty filter no-ops them) until the runner observes the artifact-side `S2SResponseCompleted` and signals stop. Without both, the response never arrives because either commit isn't sent (no fin), or the pipeline tears down before the response generates.
- **Provider errors should carry a category, not just a message (Johnny-g2n)** — `TTSError` (and by extension future `LLMError`/`STTError` migrations) now takes a `category` kwarg with literal values `quota_exceeded` / `auth_failed` / `rate_limited` / `unknown`. The pipeline's response loop reads the category to decide between (a) emit a structured `AgentTTSFailed` event for observability and continue, or (b) trip a per-session circuit breaker that suppresses every subsequent turn's answer + TTS stage. Without the category, the pipeline would either parse strings (brittle: "exceeds your quota of 10" vs "quota_exceeded" vs "Insufficient credits remaining" — every provider phrases it differently) or treat every TTS failure as terminal (over-eager: a transient 429 would silence the session for the rest of the meeting). The category sits on the exception class so it survives across the meet-worker / api boundary and the pipeline doesn't have to know which adapter raised. Old callers that don't pass `category=` inherit `"unknown"` so the broad `except TTSError` path still works.
- **ElevenLabs 401 means TWO different things — read the body (Johnny-g2n)** — ElevenLabs returns 401 for BOTH a bad / revoked API key (`{"detail": {"status": "invalid_api_key", ...}}`) AND an out-of-credits / quota-exceeded account (`{"detail": {"status": "quota_exceeded", "message": "This request exceeds your quota of 10 credits. 25 credits required."}}`). The status-code alone is not enough to categorise the failure. The adapter's `_categorise_http_failure` greps the detail string lowercased for "quota" / "credits"; matching → `quota_exceeded`, otherwise → `auth_failed`. 402/403 also map to `quota_exceeded` (paywall / billing); 429 → `rate_limited`; everything else → `unknown`. Pattern: when an upstream provider re-uses one status code for multiple semantic failures, do the disambiguation at the adapter layer where the wire format is closest at hand — the pipeline doesn't want to parse JSON bodies.
- **The TTS circuit breaker runs AFTER the router decision, not before (Johnny-g2n)** — `_respond_to_transcript_inner` publishes the `RouterDecisionMade` event first, THEN consults `self._tts_tripped`, then short-circuits with a `suppressed` decision row. The router still runs because (a) the activity log should record the model's intent even when the answer was suppressed by the breaker — operators can audit "what would the bot have said?" via decision history, and (b) the router is a cheap LLM call (typically < 500 ms / < 200 tokens) relative to the answer LLM (5-10x cost). Skipping only the expensive stage is the right cost/observability tradeoff. The alternative (skip the router too) would save ~100ms per turn but lose audit value entirely. Don't conflate "the bot can't talk" with "the bot has nothing to say".
- **AgentSpoke is "the bot tried to say X", not "the user heard X" (Johnny-tjd)** — `_answer_and_speak` publishes `AgentSpoke` whenever the answer LLM produced *any* text, even when the user barged in before the first sentence boundary flushed to TTS (so `collected` is empty and `audio_duration_ms=0`). The `audio_duration_ms` field is the signal downstream consumers use to distinguish a clean completion from a cut-before-speaking one — `> 0` means audio reached the transport, `== 0` means the LLM committed to a response but no audio played. Without this, fast barge-in mid-LLM-stream silently dropped the cut answer from the activity log and audit-log timeline: the bus showed only the post-barge-in follow-up utterance, even though the LLM had already committed tokens to a response. The old gate (`if not text or not collected: return False`) was too eager — `collected` is empty whenever the interrupt lands between deltas but before the first period, exclamation, or question mark; the new gate is `if not text: return False`. The "interrupt before ANY LLM tokens" case (no text, no audio) still returns False per the pre-existing `test_pipeline_interrupt_before_speak_skips_audio` and `test_user_resume_during_router_does_not_emit_agent_spoke` contracts.
- **Real-mode interrupt assertions assert SEMANTICS, not event counts (Johnny-tjd)** — the harness `Scenario` dataclass carries an optional `followup_keyword: str | None` field; when set, the real-provider runner's `bot_addressed_followup_keyword` assertion replaces the old `len(spoke) >= 2` count check with `(any persisted utterance contains keyword) AND (fast_barge_in_count > 0)`. Why: real LLMs phrase the redirect non-deterministically ("Regarding the launch date..." / "The launch is scheduled..." / "We're targeting end of quarter for launch") AND the cut path's `AgentSpoke` emission depends on whether the interrupt lands before or after the first sentence boundary — both make a "count + first-spoke truncation" assertion fragile. The keyword anchors the assertion on what the user actually cares about: did the bot redirect to the new topic? Older scenarios without a `followup_keyword` fall back to the count check (`bot_emitted_followup_utterance`).
- **"Bot stopped before it could start" is a valid 'stop' outcome (Johnny-gft)** — when the real LLM round-trip is slow enough (gpt-4.1-mini occasionally takes >5 s to first token) the user's interrupt arrives before any AgentSpoke event has been published. The old `_evaluate_real` treated this as a hard failure: `bot_started_speaking_before_interrupt` failed with "no AgentSpoke published". But user-visible semantic for "stop" is "the bot didn't keep talking" — and a bot that never started is just as much a successful stop as one that was cut mid-sentence. The new assertion `interrupt_observed_by_pipeline` accepts the no-spoke case IFF `fast_barge_in_count > 0` (proving the system DID detect the interrupt at the VAD level, just couldn't cut TTS that hadn't started yet). The cut-mid-sentence case still uses `first_agent_spoke_truncated` (audio_duration_ms < 4500) + `interrupt_to_cut_latency_budget`. The latency assertion is skipped when there's nothing to measure — emitting it as a hard fail in that case would have been a false negative. Don't pad `REAL_MODE_EXTRA_SILENCE_MS` higher to chase the slow-LLM edge case: that slows every scenario for the sake of one. Fix the assertion instead.
- **LLM `fetch_model_catalog` is per-adapter, dispatched at the API layer (Johnny-9eq)** — each LLM provider module (`openai_llm`, `anthropic_llm`, `gemini_llm`, `openai_compatible_llm`) exposes a module-level `async def fetch_model_catalog(api_key, *, base_url, client=None, timeout_s=15.0) -> list[LLMModelInfo]` that hits the provider's catalog endpoint and returns a typed list. - **Per-provider chat-model filter heuristics vary (Johnny-9eq)** — each provider's catalog endpoint enumerates EVERY model the account can call, not just chat-completion models, so each adapter does its own filtering: (a) **OpenAI** — substring-whitelist on the id (`gpt-`, `chatgpt-`, `o1`, `o3`, `o4`) PLUS an exclusion list for non-chat lineages (`embedding`, `tts`, `whisper`, `transcribe`, `moderation`, `realtime`, `image`, `dall-e`, `audio`). - **Frontend dynamic dropdown overrides static schema rendering on field-name match, not schema field type (Johnny-9eq)** — the LLM model picker in `/providers` overrides the per-field default rendering when `field.name === 'model' && selectedEntry.kind === 'llm'`, regardless of whether the schema declared it as TEXT (openai-compatible's free-text model id) or SELECT (OpenAI/Anthropic/Gemini's curated dropdown). - **Learnings:**
  - The terminal-vs-transient distinction is load-bearing. The bead's first instinct ("add a circuit breaker so we don't keep hammering a broken provider") is correct for `quota_exceeded` / `auth_failed` (operator intervention required) but WRONG for `rate_limited` (provider says "back off" — the next turn arrives ~10 s later anyway and is likely to succeed). Encoding the category-to-terminal mapping at one source of truth (`TERMINAL_TTS_FAILURE_CATEGORIES`) makes the breaker policy auditable and means adding a new category (e.g. `model_overloaded`) is one line.
  - mypy doesn't narrow `Any` via `in (literal, literal, ...)` membership checks. The natural shape `category = getattr(exc, 'category', None); if category in (... literals ...): return category` fails with `no-any-return`. The fix is explicit `==` checks per branch: `if category == "quota_exceeded": return "quota_exceeded"; ...`. Slightly more verbose, mypy-clean. Worth remembering for any future "unsafely-typed string → typed Literal" coercion.
  - The api image bakes the Python source via `COPY .` (production-shape, no bind mount unless `./run-dev.sh`). Editing `app/providers/elevenlabs_tts.py` on the host requires `docker compose build api worker migrate && docker compose up -d api worker` before the change is in the container's filesystem. Forgetting this means the api keeps running the OLD code while tests in the worker container (which has the bind mount) pass against the new code — silent divergence between unit tests and live behaviour. Per-iteration ritual: rebuild after every provider/pipeline edit.
  - The pipeline's existing event-bus convention (multiplexed channel, every event type shares the wire) made adding the new event trivial — no new pub/sub plumbing, no WS routing change, just the schema + the publish call. `WIRE_TYPE_MAP` only renames event types whose internal name differs from the AC wire name; `agent_tts_failed` matches its wire form already so the pass-through default in `to_wire_type` does the right thing. Pattern: new event types are cheap to add precisely because the bus is opinionated about being dumb.
  - In-browser unit testing via `window.WebSocket` patching works well as a fallback when (a) the failure path requires expensive real provider state (an actually-exhausted ElevenLabs key) and (b) the goal is verifying the UI surface, not the wire protocol. Inject a synthetic frame post-`open`, assert the rendered DOM. Cleaner than mocking the entire backend. Resets cleanly via `navigate_page reload`.

## Codebase Patterns (Study These First) — added this iteration
- **Tier-paywall smoke failures land at the e2e runner, not preflight (Johnny-uga)**: provider tier limitations (ElevenLabs free-tier library voices, future model-not-included-in-plan cases) are detected by matching the smoke-test detail string against a per-provider substring table (`_TIER_PAYWALL_PATTERNS` in `backend/tests/e2e/providers_ui/runner.py`). Matched failures convert the plan outcome from FAIL → SKIP with an actionable hint (voice id + remediation). The matcher is intentionally narrow — only known tier-paywall phrasings trip; genuine FAILs (bad request, server error, 5xx, network) stay FAIL. Why not preflight: ElevenLabs metadata routes (`/v1/voices`, `/v2/voices`) return 200 for paywalled-on-this-tier voices; only the actual TTS endpoint reliably returns the explicit free-tier 402, so a preflight probe would either be unreliable or burn a credit per run. Add a new provider entry to `_TIER_PAYWALL_PATTERNS` (kept narrow on purpose — one substring per known wording, lowercased match) when a new provider surfaces a tier paywall.
- **Unit tests for `providers_ui` runner internals belong OUTSIDE the `providers_ui/` directory (Johnny-uga)**: `tests/e2e/providers_ui/conftest.py` declares a session-scoped autouse `_require_live_stack` fixture that calls `pytest.skip(...)` whenever `http://localhost:8000/health` is unreachable. That fixture fires for EVERY test in the directory, including ones that don't depend on the live stack — so a pure-function unit test placed inside the package will silently skip in any environment without the api exposed on localhost. The fix is to put the file one level up (`tests/e2e/test_*.py`) so the autouse fixture's directory scope doesn't capture it. Same caveat applies to any future "test the runner / preflight / report logic in isolation" file.
