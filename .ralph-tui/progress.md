## Codebase Patterns (Study These First)

- **Frontend layout owns `<main>`**: `frontend/src/routes/+layout.svelte` wraps `{@render children()}` in `<main class="content">`. Route pages MUST NOT render their own `<main>` element (invalid nested landmarks). Use `<section>`, `<div>`, or just bare elements inside route `+page.svelte` files.
- **Active-route detection**: Use `import { page } from '$app/state'` (Svelte 5 runes API in SvelteKit 2.16+). Compare `page.url.pathname` with `href`. Apply both a class (`class:active`) and `aria-current="page"` for a11y.
- **Browser verification fallback**: `.mcp.json` declares `chrome-devtools-mcp` for future sessions, but MCPs load at session start so they can't be used in the same iteration they're added. For one-shot verification, `npx playwright` works: `npm install playwright` in `/tmp`, then `npx playwright install chromium`, then a small `.mjs` script that captures screenshots to `.ralph-tui/reports/`.
- **Frontend quality gates**: `pnpm typecheck` runs `svelte-kit sync && svelte-check`; `pnpm lint` runs ESLint. Both must be invoked from `frontend/`.
- **Backend quality gates**: `uv run pytest`, `uv run ruff check`, `uv run mypy` from `backend/`.
- **DB layer location**: SQLAlchemy 2.0 models live in `backend/app/db/models.py`; declarative `Base` in `backend/app/db/base.py`; engine + `SessionLocal` + `session_scope()` context manager in `backend/app/db/session.py`. `app.config.get_settings()` reads `DATABASE_URL` from env (default points at compose `postgres`). All public models re-exported from `app.db.__init__`.
- **Portable enum + JSON columns**: For tests without PostgreSQL, use `SAEnum(..., native_enum=False, length=N)` (renders as `VARCHAR + CHECK`) and `_json_column()` helper in `app/db/models.py` (`JSON().with_variant(JSONB(), "postgresql")`). Keeps tests dialect-agnostic while preserving JSONB on real DB. Enum classes use `enum.StrEnum` (Python 3.11+) — ruff's `UP042` rejects `class Foo(str, enum.Enum)`.
- **Alembic conventions**: `backend/alembic.ini` is minimal; `backend/alembic/env.py` reads URL from `app.config.get_settings()` and imports `app.db.models` to register metadata. Initial migration `0001_initial_schema.py` is hand-written (autogenerate can't see `Vector` types properly). `op.execute("CREATE EXTENSION IF NOT EXISTS vector")` runs first in `upgrade()`. Test migrations end-to-end with `docker run -d pgvector/pgvector:pg16 -p 55432:5432 ...`, then `DATABASE_URL='postgresql+psycopg://...:55432/...' uv run alembic upgrade head`.
- **pgvector typing**: `pgvector.sqlalchemy` has no `py.typed` marker — add `[[tool.mypy.overrides]] module = "pgvector.*" / ignore_missing_imports = true` to `pyproject.toml`. SQLAlchemy `Enum` is non-generic in stubs; don't parameterize the return type of helper factories.
- **Compose env vars are shared via YAML anchor**: `x-backend-env: &backend-env` at the top of `docker-compose.yml`, then `environment: *backend-env` on both `api` and `worker`. Keeps DATABASE_URL/REDIS_URL/Google/provider keys in one place. New env vars go in the anchor block plus `.env.example`.
- **Backend image uses `/workspace` WORKDIR**: avoids the confusing `/app/app/` path that comes from naming both the WORKDIR and the source package `app`. Inside the image, source lives at `/workspace/app/`, alembic at `/workspace/alembic/`. uv installs the package into `/opt/venv`, which is first on `PATH`.
- **Vite in alpine: use `127.0.0.1` in healthchecks**: `localhost` inside `node:20-alpine` resolves to IPv6 `::1`, but vite binds IPv4 only — `wget http://localhost:5173` fails with "Connection refused" even though the host port works. Use `wget -q --spider http://127.0.0.1:5173`. The api (python:3.12-slim) uses urllib which falls back, so `localhost` is fine there.
- **Vite arg-forwarding: use `pnpm exec vite`**: `pnpm run dev -- --host 0.0.0.0` passes `--` literally to vite, which then doesn't recognize `--host` (vite log shows "use --host to expose" hint). Use `CMD ["pnpm", "exec", "vite", "dev", "--host", "0.0.0.0", "--port", "5173"]` in the frontend Dockerfile to bypass the npm-script arg dance.
- **Worker healthcheck via heartbeat file**: The placeholder worker (`backend/app/worker.py`) writes `time.time()` to `/var/lib/johnny/worker/heartbeat` every 5s; healthcheck is `python -c "...; sys.exit(0 if os.path.exists(p) and time.time() - os.path.getmtime(p) < 30 else 1)"`. Avoids adding `procps`/`curl` to the slim image. `write_heartbeat(path)` accepts a path argument so tests can use `tmp_path` instead of writing to `/var/lib`.
- **Backend Dockerfile uv install**: `pip install --no-cache-dir uv==0.11.19` (matches local mise install for reproducibility). Two-stage `uv sync`: first `--no-install-project --no-dev` (caches deps when only source changes), then full `--no-dev` after copying source. `PATH="/opt/venv/bin:$PATH"` so `uvicorn`/`python` resolve to the venv binaries.
- **Two top-level packages in `backend/`**: `app/` is the FastAPI API/worker code; `johnny/` is meet-worker runtime code that ships in a different image. Both are listed in `[tool.hatch.build.targets.wheel].packages = ["app", "johnny"]` and in `[tool.mypy].files`, so quality gates cover both. Keep meet-worker code free of FastAPI/SQLAlchemy imports — the meet-worker image deliberately doesn't install those deps.
- **Compose "build-only" services use `profiles:`**: A service like `meet-worker` with `profiles: ["meet-worker"]` is *excluded* from default `docker compose up` and `docker compose build`, but `docker compose --profile meet-worker build meet-worker` builds it on demand. The `image: name:tag` line tags the result so the Docker SDK (US-029/US-030) can `docker run` it later. Pattern for "image is part of the project but not part of the running stack."
- **PulseAudio in Docker — virtual mic via remap-source**: Browser-microphone simulation needs three modules: `module-null-sink` for the *speaker* (browser plays here, we capture `<sink>.monitor`); a *second* `module-null-sink` as a loopback target; `module-remap-source` over the loopback's `.monitor` to expose a stable source name to the browser. Then `pactl set-default-sink/source` so Chromium auto-picks them. See `backend/meet-worker-entrypoint.sh` for the canonical sequence.
- **Playwright Python base image**: `mcr.microsoft.com/playwright/python:v1.49.0-jammy` already has Chromium + Playwright Python installed system-wide. No need to `pip install playwright` or download browsers — just `apt-get install xvfb pulseaudio pulseaudio-utils dbus-x11 x11-utils` for the A/V/X11 environment and you're set. `dbus-x11` is non-obvious but Chromium needs a session bus to start cleanly.
- **Selfcheck pattern**: `python -m johnny.meet_worker.selfcheck` shells out to `pactl list short sinks/sources` (tab-separated; column 1 is the name) and verifies the expected names are present. Mockable with `unittest.mock.patch("subprocess.run")` for fast unit tests; runnable inside the container for an integration smoke test. Sink/source names overridable via `JOHNNY_SINK_NAME` / `JOHNNY_SOURCE_NAME` env vars so the same image can be reconfigured.
- **Audio bridge — parec/pacat over subprocess.PIPE**: `MeetAudioBridge` (`johnny/meet_worker/audio_bridge.py`) shells out to `parec --device=<sink>.monitor --rate=16000 --channels=1 --format=s16le --raw` for capture and `pacat --playback --device=<source>_loopback ...` for playback. Subprocess stdout/stdin are read/written via `loop.run_in_executor(None, fn, ...)` so the asyncio loop never blocks on the OS pipe. No external Python deps — keeps the meet-worker image free of numpy/scipy/audioop (latter is removed in 3.13).
- **Bounded asyncio queue with EOS sentinel + slot reserve**: For real-time capture, `asyncio.Queue(maxsize=N+1)` lets the producer always have room for a trailing `None` sentinel that signals EOF to the async-generator consumer. While streaming, the pump drops the oldest frame whenever `qsize() >= N` to keep latency bounded; on EOF, `put_nowait(None)` is wrapped in `suppress(QueueFull)` for defensive paranoia. Without the +1 reserve, the sentinel push would block forever when the queue is at user-facing capacity.
- **Resampling without numpy**: `resample_pcm16(pcm, src, dst)` uses `array.array("h")` + linear interpolation in pure Python. Adequate for sub-second 8k/16k/24k/48k voice chunks; not anti-aliased, so aggressive downsampling will alias HF content. For test correctness: a constant signal must round-trip exactly (`all(s == 1000)`); a 440 Hz sine at 48 kHz → 16 kHz preserves peak amplitude within ~10%; ramp signal preserves endpoints exactly.
- **Protocol-typed subprocess for testable I/O**: Defining a `_Process` `typing.Protocol` (`stdout: IO[bytes] | None`, `stdin: IO[bytes] | None`, `poll/terminate/kill/wait`) lets `subprocess.Popen[bytes]` satisfy the same shape as a `_FakeProcess` wrapping `io.BytesIO`. Override `_spawn_capture_process` / `_spawn_playback_process` in a `_FakeBridge` subclass to inject the fakes in tests — no `unittest.mock.patch` ceremony. Note: protocol-Attribute types are invariant in mypy strict — type the fake's `stdin: IO[bytes] | None` (not `_FakeStdin | None`) and `isinstance`-narrow in tests that need the subtype.
- **Provider ABCs — async generators declared on sync `def`**: Streaming ABC methods like `STTProvider.transcribe_stream` and `TTSProvider.synthesize_stream` are declared as `@abstractmethod def foo(...) -> AsyncIterator[T]: ...` (NOT `async def`). The signature returns `AsyncIterator[T]`; the implementor writes `async def foo(...)` with `yield` statements — the language transforms the body into an async-generator that *is* an `AsyncIterator[T]`. Declaring the base as `async def` would mark it a coroutine, not an iterator factory, and confuses both mypy and runtime semantics. `LLMProvider.chat`, by contrast, is `async def` because it returns a single coroutine resolving to `LLMResponse`.
- **`ruff B027` for intentional non-abstract ABC hooks**: When you want an empty default implementation in an ABC (e.g., `async def close(self) -> None:` as a hook subclasses *may* override), ruff flags it as B027 ("forgot @abstractmethod?"). Suppress with `# noqa: B027 — intentional non-abstract hook` rather than adding a `pass` (still empty) or making it abstract (forces every stateless adapter to write boilerplate).
- **Single-table sqlite fixture for ORM unit tests**: When only one or two tables need a real DB (e.g., `provider_credentials` for the loader tests) and other tables have backend-specific column types like `pgvector.Vector`, use `Base.metadata.create_all(engine, tables=[Model.__table__])` to create just the table(s) you need against in-memory sqlite. SQLAlchemy's `Model.__table__` is typed as `FromClause` in stubs but is `Table` at runtime — needs `# type: ignore[list-item]` on the `tables=[...]` arg under mypy strict. Pattern keeps DB-touching tests fast and dialect-portable.
- **Provider registry vs DB rows split**: `app.providers.base.ProviderRegistry` maps `(ProviderKind, name)` → factory. Adapter modules register their *factories* at import time; the registry knows nothing about credentials. The DB table `provider_credentials` says which providers are *active*. `load_active_providers(session)` (now in `app/providers/loader.py`) is the bridge — reads active rows, decrypts credentials, builds a `ProviderConfig`, and calls the registered factory. Unknown `provider_name` in the DB raises `UnknownProviderError` so misconfiguration fails fast at startup, not mid-meeting.

To keep the meet-worker free of FastAPI/SQLAlchemy, `base.py` holds only ABCs / value objects / `ProviderKind` (StrEnum) / `ProviderRegistry`. The DB-coupled `load_active_providers` lives in `app/providers/loader.py` and must be imported explicitly. `app/providers/__init__.py` only re-exports from `base.py`. `app/db/models.py` imports `ProviderKind` from `app/providers/base.py` (use `from ... import ProviderKind as ProviderKind` so mypy strict counts it as re-exported when downstream `app/db/__init__.py` re-exports it again).

- **Stdlib-only adapter auto-registration in `app/providers/__init__.py`**: Adapters whose import has no heavy optional deps (only stdlib + `app.providers.base`) register at package import time, e.g. `from app.providers.piper_tts import register as _register_piper_tts; _register_piper_tts(replace=True)`. Heavyweight adapters (torch, openai-sdk, etc.) must register lazily from their own modules or via an explicit hook called by the API startup. `replace=True` keeps the call idempotent under pytest reloads.
- **Subprocess-driven TTS adapter pattern**: Local TTS via the `piper` binary follows the same `_Process` Protocol + override-`_spawn_process` testing pattern as `MeetAudioBridge`. The adapter spawns a fresh subprocess per `synthesize_stream` call (piper exits on stdin close), writes text+newline to stdin, reads raw S16LE PCM from stdout, resamples to 16 kHz, yields aligned frames. A `carry` buffer holds any 1-byte tail across chunk reads so `_resample_pcm16` always sees an even-length input. `try/finally` around the `yield` loop ensures `_cleanup` (terminate + wait + kill-on-timeout) runs even when the consumer breaks early or `aclose()`s the generator.
- **Shared provider contract via `_<kind>_contract.py` private module**: For provider-kind contract assertions reused across adapters, drop a leading-underscore helper module into `tests/providers/_tts_contract.py` (pytest does not collect underscore-prefixed files). Export one `async def assert_synthesize_yields_pcm_audio(adapter, ...)` that exercises the streaming contract and returns the concatenated audio so adapter-specific tests can layer extra assertions on top. Each adapter test file (`test_piper_tts.py`, future `test_elevenlabs_tts.py`, …) ends with a one-line `await assert_synthesize_yields_pcm_audio(...)` test so pytest reports show "this adapter passes the contract". STT mirrors the pattern in `_stt_contract.py` with two helpers: `assert_transcribe_yields_events` (single-chunk shape — what the pipeline actually uses) and `assert_transcribe_respects_vad_boundaries` (multi-chunk shape — proves the adapter concatenates rather than fixed-windows).
- **Lazy-import heavy ML adapter pattern (US-013 / FasterWhisperSTT)**: For adapters that depend on a large ML library (faster-whisper, torch, onnxruntime) you still want to ship in the meet-worker image but NOT in the API container, do all heavy imports lazily inside the `_load_model` hook (via `importlib.import_module`). The module-level imports are stdlib-only, so `app/providers/__init__.py` can still auto-register the adapter at import time without the library installed. `_load_model` raises `STTError` ("faster-whisper is not installed; install via …") on `ImportError`, so misconfiguration fails loud at first use, not at startup. Tests override `_load_model` to inject a `_FakeModel` and never touch the real library. Optional install group: `[project.optional-dependencies] local-stt = ["faster-whisper>=1.0.0"]`, with the meet-worker Dockerfile doing a direct `pip install` since the meet-worker doesn't install the project as a package.
- **Async-lazy-loaded model with `asyncio.Lock`**: For an adapter that caches an expensive object (`WhisperModel`, an HTTP session, etc.) on first call, guard the load with `self._model_lock = asyncio.Lock()` + `async with self._model_lock: if self._model is None: self._model = await asyncio.to_thread(self._load_model)`. Prevents multiple concurrent `transcribe_stream` calls from each kicking off a model load. The `asyncio.to_thread(self._load_model)` keeps the (~1–10 s) blocking import out of the event loop. `close()` just sets `self._model = None`, so the next call reloads — useful for tests asserting load behaviour without re-instantiating the adapter.
- **Numpy-or-array.array fallback for PCM→float32**: `_pcm16_bytes_to_float32(pcm)` tries `import_module("numpy")` and returns a numpy `ndarray` when available, else returns `array.array("f", [s / 32768.0 for s in samples])`. Production has numpy (faster-whisper requires it); the test environment doesn't (we never call the real library, only a fake model that returns scripted segments), so the module stays importable. Use `monkeypatch.setattr("app.providers.faster_whisper_stt.import_module", _no_numpy)` in tests to force the fallback path explicitly.
- **Whisper `avg_logprob` → confidence**: faster-whisper's `Segment.avg_logprob` is the natural-log probability averaged across tokens. `confidence = exp(avg_logprob)` gives the geometric-mean per-token probability, a reasonable `[0, 1]` confidence proxy. Defensive helper: `_logprob_to_confidence(logprob)` returns `None` for `None` / `NaN` / `±inf` inputs, and clamps the result to `[0, 1]` so unexpectedly positive log-probs don't blow up.
- **`AsyncIterator[T]` return type lacks `aclose`**: `TTSProvider.synthesize_stream` is declared returning `AsyncIterator[bytes]` (per the ABC), but the implementation is an async generator. To call `.aclose()` from a test, cast the return value: `agen = cast(AsyncGenerator[bytes, None], adapter.synthesize_stream("hi"))` — mypy will reject `agen.aclose()` on the narrower `AsyncIterator` type. Same applies to `.athrow()` / `.asend()`.
- **Fake stdin BytesIO must NOT actually close on `.close()`**: When a fake subprocess's stdin (an `io.BytesIO` subclass) records writes for test assertions, override `close()` to flip a `close_called` flag *without* calling `super().close()`. Otherwise `.getvalue()` raises `ValueError: I/O operation on closed file` in subsequent assertions that inspect what was written.
- **Shared resampler in `app/providers/_pcm.py`**: Once two adapters need linear-interpolation S16LE resampling (e.g., PiperTTS 22.05 kHz → 16 kHz and OpenAITTS 24 kHz → 16 kHz), extract into `app/providers/_pcm.resample_pcm16`. The leading-underscore module name keeps it package-private; piper_tts.py imports it and exposes `_resample_pcm16 = resample_pcm16` as a backward-compat alias for existing tests. The duplicate copy in `johnny/meet_worker/audio_bridge.py` stays — meet-worker must not import from `app.providers` for the bridge (separation of concerns).
- **httpx `MockTransport` for streaming-response adapter tests**: `httpx.MockTransport(handler)` accepts a sync handler `Callable[[Request], Response]`. For streaming bodies, build the `Response` with `content=<async-iterator-factory>` — `httpx` accepts both bytes and iterators. Override the adapter's `_create_client()` hook to inject `httpx.AsyncClient(transport=httpx.MockTransport(handler))`. Cleaner than monkey-patching httpx internals; mirrors PiperTTS's `_spawn_process` injection pattern.
- **Cloud TTS adapter shape (US-016 pattern)**: `__init__` validates config → eager `self._client = self._create_client()` so the client is reused across calls; `synthesize_stream(text, voice_id=None)` is an `async def` generator that calls `async with self._client.stream(...) as response:` and yields aligned S16 frames; `close()` calls `await self._client.aclose()` (suppress exceptions). Cancellation: when the consumer `aclose()`s the generator, `GeneratorExit` propagates through the `yield`, then through the `async with`, which closes the underlying response and connection — no manual cleanup needed.
- **Cloud TTS error mapping**: Wrap the `async with client.stream(...)` body in `try/except httpx.HTTPError`. Inside, call `_raise_for_status(response)` which `await response.aread()`s the (small) error body, tries to parse JSON for a `{"error": {"message": ...}}` (OpenAI) or `{"detail": {"message"}}` / `{"detail": "..."}` (ElevenLabs) shape, and raises `TTSError(f"...HTTP {status}: {detail}")`. The outer `except httpx.HTTPError` catches network/timeout errors and translates them into `TTSError("provider ... request failed: ...")`. The `if isinstance(exc, TTSError): raise` guard prevents double-wrapping when `_raise_for_status` already raised.
- **ElevenLabs `pcm_16000` output_format saves a resampling step**: ElevenLabs streams 16 kHz mono S16LE directly when `?output_format=pcm_16000` is set. No resampler needed, just carry-byte alignment. OpenAI's `response_format=pcm` is 24 kHz mono S16LE — needs resampling. Always check the provider's PCM output sample rate when wiring a new cloud TTS adapter.
- **Meet-worker image must `pip install httpx` when `app/providers/__init__.py` auto-registers cloud adapters**: Adding `openai_tts.py` / `elevenlabs_tts.py` to the auto-register block makes `import app.providers` pull in `httpx` at module level. The meet-worker copies `app/providers/` into its image, so the missing `httpx` would break `from app.providers import STTProvider` at runtime. - **Single adapter for the entire OpenAI-compatible ecosystem**: vLLM, Ollama, LM Studio, llama.cpp's `server`, OpenRouter, Together all speak the same `/v1/chat/completions` schema. The `OpenAICompatibleLLM` adapter (registered name: `"openai-compatible"`) wraps all of them. - **Tool-call argument shape varies across OpenAI-compatible servers**: OpenAI canonical: `function.arguments` is a JSON-encoded string. Ollama: it's a raw object. - **Hermes-style tool calling pattern**: (1) inject `<tools>...</tools>` block + example `<tool_call>{json}</tool_call>` block into the system message (prepend a new system or extend the existing one — don't drop the user's system prompt). Implemented the desktop OAuth 2.0 authorization-code flow against

future Google API calls (calendar, userinfo) go through to get

### Files created
- `backend/app/services/google_oauth.py` — pure async helpers:
  `build_authorize_url`, `exchange_code_for_tokens`, `refresh_access_token`,
  `fetch_userinfo`, `revoke_token`. All accept an optional `http_client`
  so `httpx.MockTransport` can drive them in tests; the default

  to one `GoogleAccount` row and one SQLAlchemy session; on every

  if needed, retries once on 401, and persists rotated refresh tokens
  back to the encrypted row.
- `backend/app/api/auth.py` — `POST /auth/google/start` returns the
  consent URL with a server-generated `state`; `POST /auth/google/callback`
  exchanges the code, fetches userinfo, and upserts a `google_accounts`
  row. State map is in-memory (single-user, single-process). Returns
  `AccountRead` (no token material exposed).
- `backend/tests/services/test_google_oauth.py` (16 tests),
  `backend/tests/services/test_google_client.py` (14 tests),
  `backend/tests/api/test_auth.py` (13 tests).

### Files modified

  `google_client_secret`, `google_oauth_redirect_uri`.
- `backend/app/main.py` — registered `auth_router`.

### Learnings
- **httpx over `google-auth` SDK for OAuth flows**: The `google-auth`
  package pulls a long transitive dependency chain
  (`requests`+`cachetools`+`pyasn1`+...). Since the desktop OAuth
  protocol is just POST to a couple of well-known endpoints with form
  data and bearer tokens for userinfo, doing it directly via httpx
  is ~50 lines per helper and keeps `httpx.MockTransport` available
  for tests. Mirrors the existing cloud-LLM adapter pattern.
- **Refresh-token rotation: persist whichever token Google emits**:
  Google's token endpoint *usually* omits `refresh_token` in
  refresh responses (rotation is rare), but occasionally returns
  a new one. The parser uses `fallback_refresh_token` so callers
  always have a valid token to persist, but `GoogleApiClient._refresh`
  detects rotation (`new != old`) and re-encrypts. Tests cover both
  paths.
- **SQLite drops timezones from `DateTime(timezone=True)`**: The
  ORM column is `DateTime(timezone=True)` so PostgreSQL stores
  `TIMESTAMPTZ`, but SQLite stores text and returns naive values
  on read. `_access_token_is_fresh` defensively coerces naive
  `expires_at` to UTC before comparing. Same pattern needed in tests
  that compare round-tripped datetimes.
- **Cascade-aware single-table SQLite fixtures**: `GoogleAccount` has a
  `calendar_events: relationship(cascade="all, delete-orphan")`.
  `session.delete(account)` then issues a `SELECT FROM calendar_events`
  to load related rows. The single-table fixture pattern doesn't work
  alone — include `CalendarEvent.__table__` in the `tables=[...]`
  arg even if the test never touches calendar events. Same gotcha
  applies to any FK relationship with `cascade="all, delete-orphan"`.
- **FastAPI `Depends(get_settings)` doesn't reach module-level
  `_get_crypto()`**: `get_crypto` in `app/api/deps.py` calls the
  module-level `app.security.crypto.get_crypto`, which reads
  `get_settings()` directly (not via `Depends`). Overriding only
  `app.dependency_overrides[get_settings]` won't propagate to the
  crypto dep — tests that exercise the no-FERNET-KEY path must
  also override `get_crypto` (or set the global `Settings`).
- **In-memory pending-state map for OAuth `state`**: Single-user,
  single-process means a `dict[str, _PendingState]` at module
  level is sufficient. Pop on use (`_consume_state`) so replays
  fail. The auth tests autoclear the map in a fixture so test
  isolation is preserved. If we ever scale to multi-process,
  swap for Redis with TTL.
- **Verbatim secret check on response**: The provider tests
  asserted `assert "sk-test" not in resp.text` to guarantee no
  secret leaks. The OAuth tests apply the same idea: after
  `/callback`, assert the JSON has no `refresh_token` /
  `access_token` / `*_encrypted` keys. Cheap and catches future
  drift if someone adds a "debug" field to `AccountRead`.

### Codebase pattern promotions
- **Auth & API client split — OAuth helpers vs persistent wrapper**:
  `app/services/google_oauth.py` is pure (no SQLAlchemy, no DB) —
  it just talks HTTP to Google. `app/services/google_client.py`
  binds an OAuth flow to a `GoogleAccount` row + a SQLAlchemy
  session and handles persistence of rotated tokens. This split
  mirrors the existing provider-base (ABCs in `app/providers/base.py`,
  SQL-backed loader in `app/providers/loader.py`) and keeps the
  voice pipeline / future meet-worker free of SQLAlchemy if they
  only need OAuth math.
- **httpx adapter "ownership" pattern for top-level helpers**:
  Each helper accepts `http_client: httpx.AsyncClient | None = None`.
  When `None`, the helper constructs a per-call client and closes
  it in `finally`; when supplied, the helper just uses it and
  leaves the caller to close. Lets production code share a long-lived
  client when desired (e.g. inside `GoogleApiClient`) while tests
  inject a `httpx.MockTransport`-backed client.
- **401-retry with mid-request refresh**: `GoogleApiClient.request`
  fetches a token, sends the request, and if the response is 401
  forces a fresh refresh and retries *exactly once*. Google
  occasionally invalidates tokens server-side before the stated
  expiry; the single retry keeps the user-facing API code free
  of refresh logic. Other status codes (403, 5xx) are returned
  unchanged for the caller to handle.

NoopDecisionSink returns `None` — the pipeline sees that and short-circuits the approval round (logged as "no id; treating as rejected"), preventing a confusing "approval pending event with decision_id=0" path. (Promoted.)
  - **`DecisionRecord` unfrozen to support `update_outcome`**: in-memory tests need to flip the outcome in place after the gate resolves. Adding a `set_outcome` method would be cleaner OO-design but the test/assert ergonomics of "compare snapshot to expected list of dataclasses" are much better with a single direct field assignment. The dataclass-frozen-vs-mutable trade-off resolves toward mutable when the value is conceptually a row in a table that gets UPDATEs. (Promoted.)
  - **Sibling-channel pattern: `johnny.approval.{session_id}` is the *control* channel for approve/reject signals**: separate from `johnny.session.{session_id}` (live UI updates) and `johnny.global.*` (cross-cutting). API → meet-worker direction only; the meet-worker subscribes (RedisApprovalGate), the API publishes (`publish_approval`). UI events about approvals (`ApprovalPending` / `ApprovalResolved`) flow on the regular `johnny.session.*` channel via the existing `RedisEventBus`. Three-channel namespacing keeps the consumer side clean: each subscriber's psubscribe pattern matches exactly one role. (Promoted.)
  - **Backend Dockerfile must `COPY johnny ./johnny`**: once `app/services/*.py` imports anything from `johnny.voice_pipeline.*`, the API container needs the `johnny/` source tree even though it's nominally the meet-worker package. The pyproject `[tool.hatch.build.targets.wheel].packages = ["app", "johnny"]` declaration means `uv sync` happily installs both — but only if both directory trees exist in the build context. This was a regression-class fix because all previous stories had clean separation (API touched `app/`, meet-worker touched `johnny/`); US-027's `app/services/approval.py` is the first cross-import that breaks the symmetry. (Promoted.)
  - **`sessionStorage` to gate "request notification permission once per session"**: cleaner than reading `Notification.permission` repeatedly — the latter is `"default"` both before the first request and after a programmatic dismissal, so it can't distinguish "never asked" from "user dismissed". A session-scoped flag (`johnny.notification-permission-requested`) plus a final `Notification.permission` read is the right combo: ask once, then trust the browser's persistent state.
  - **Service worker as a SvelteKit static asset**: dropping `service-worker.js` into `frontend/static/` makes Vite serve it at `/service-worker.js` with the correct MIME and scope `/`. Avoids SvelteKit's `src/service-worker.ts` integration which would also bundle the worker via Vite — overkill here because we want plain ES5-flavoured JS that runs in old browsers and has no SvelteKit imports. Registered with `{ type: 'classic' }` to match the file's syntax.
  - **In-UI approval panel uses Svelte 5 `$state` array; non-reactive `Map<>` for cleanup state**: `pendingApprovals: PendingApproval[]` is `$state` so the panel re-renders when items are added/removed. `approvalSubscriptions: Map<sessionId, Subscription>` and `approvalTimers: Map<decisionId, Timer>` are plain Maps because their values are imperative resources (WS handle, setTimeout id) — making them `$state` would cause unnecessary re-renders and the values aren't used in the template. (Promoted.)
  - **Per-session WS subscription managed by the layout**: a `syncApprovalSubscriptions()` helper reconciles the desired set (`activeSessions` filtered to live statuses) against the existing `approvalSubscriptions` map — adds subs for new sessions, closes subs for ended ones (and drops any pending approvals belonging to those sessions). The layout doesn't try to be clever about "which page wants which sub"; it just owns every active session's WS so approval prompts work no matter what route the user is on. The future per-session detail view will open its own WS subscription independently.
  - **`subscribers` field in the approve/reject API response**: Redis `publish` returns the count of subscribers it delivered to. Returning that to the frontend gives the UI a signal that "this approval was sent into the void" — useful for telling the user "the meet-worker isn't listening, your action was lost" — but the API doesn't reject the call (it could just be a transient gap during reconnect). 0 vs >0 is observability, not authorization.
  - **The approval gate's timeout is the *server-side* auto-reject window**: client-side, the layout also schedules a setTimeout(`timeoutS * 1000 + 500ms`) that clears the entry if no `approval_resolved` event arrives. Defense-in-depth: server might publish nothing (race condition, network blip), client side still tidies up so the UI doesn't accumulate stale prompts.
  - **`type(exc).__name__ == "..."` is irrelevant here — `redis.exceptions.TimeoutError` is caught directly** because `RedisApprovalGate._connect` lazy-imports redis but the `try/except TimeoutError` at the `asyncio.wait_for` site is the asyncio builtin, not redis's. Distinct from the docker_launcher pattern where the SDK exception class can't be imported because docker SDK may be missing. The redis client is a required dep for the meet-worker that exercises the gate, so a hard `from redis.asyncio import Redis` at usage time is fine.
