## Codebase Patterns (Study These First)

- **Out-of-band speech with a turn terminal (`say()` pattern, trt.17)**: `session.say()` fires `speech_created` with `source="say"`, so the `generate_reply` FIFO (`RouterGate.bind_reply`) never sees it — attach the done-callback to the returned `SpeechHandle` directly and route the terminal through `TurnLedger.emit` (first-wins makes duplicate callbacks safe). The seam is attached post-construction (`gate.attach_say(self.session.say)` in `JohnnyAgent.on_enter`) because the AgentSession doesn't exist at gate build time — same shape as `attach_approval`.
- **Row-before-ack (trt.17/.18)**: never speak a promise before the durable row exists — `await TaskCoordinator.begin()` first, speak only on a non-None `QueuedTask`; every failure leg (no coordinator, no say, persist failure, say raising) speaks nothing and terminalizes `no_reply(stage_error)`. Check "can I speak" (say attached) *before* queueing, so an unspeakable ack queues nothing.
- **Browser-validating router actions before trt.19's catalog**: the live router model has no delegation guidance until the task catalog lands — steer it via the playground System prompt (→ `RouterGateConfig.instructions`, rendered as "Meeting instructions"), spelling out exact schema fields (`action`, `task {kind, args, ack}`). llama3.2:3b complies first-try. Fake-mic method: synthesize utterances with known text in-image (piper CLI), stitch 48 kHz mono WAV, relaunch Chrome with `--use-file-for-fake-audio-capture` (see `.validation/Johnny-trt.17/gen_fake_mic_trt17.py` + LATENCY.md); restore Chrome flags after.
- **Timing-row caveats (LATENCY.md, verified again)**: STT rows attach to the *previous* turn_id (Johnny-5vb) — pair by timestamp; the no-answer-hop proof for say()-driven turns is the *absence* of `answer_llm` rows for the turn.
- **Gate-emitted timing rows (trt.19)**: the router LLM is a *side* call LiveKit emits no metric for — when a stage needs a `session_timings` row, time it in `run_turn` *around* `run_gate` and emit through an injected `RecordTriageTiming`-style seam AFTER the decision checks (timed-out/barged gates emit only their terminal). Gate-emitted rows stamp `started_at_ms` at stage START (the documented field semantic), unlike LiveKit-metric rows which are END-stamped — consumers of gate rows need no `- duration_ms` compensation. `stage="router_llm"` is already in the subscriber whitelist; no migration.
- **Capability gating for prompt content (trt.19)**: never advertise a capability the runtime can't honour — `task_catalog` fills only when `task_coordinator is not None` (same `_build_sync_persistence` gate as the sink), so the router is never taught kinds that could only `stage_error`. The catalog renderer returns `""` for an empty tuple so the no-catalog prompt stays byte-identical (replay-parity by construction; pin with a both-ways prompt test).
- **Shadow observability via `decision.raw` (trt.50)**: to persist per-turn diagnostic data with NO migration/event/subscriber change, mutate the parsed decision's `raw` dict in the gate *before* `record_decision` — the existing `RouterDecisionMade` emit (`raw_output=dict(decision.raw)`) lands it in `agent_decisions.raw_output`. Parity-safe because the replay diff compares only `should_speak`/`terminal_state`/`outcome`/`spoke_text`; the producer must never raise into the turn (catch-all → key absent) — pin both with tests. Compute pre-LLM work *outside* the `router_llm` timing span so trt.19 rows stay baseline-comparable.
- **Dev-stack surface split + one-off containers (trt.50)**: the playground gate runs in the bind-mounted **api** service (uvicorn hot-reload picks up gate edits); the **agent-worker** (Meet surface) bakes source — rebuild it (`docker compose build agent-worker && docker compose up -d agent-worker`) before live-validating gate changes there. `docker compose run` one-offs do NOT inherit `docker-compose.dev.yml` (only run-dev.sh layers it) — pass `-f docker-compose.yml -f docker-compose.dev.yml` explicitly or the container runs the baked image without your edits. api's default log level is WARNING — prove INFO/DEBUG log lines via pytest `--log-cli-level=DEBUG`, not `docker compose logs`.
- **Multilingual (EN/RU/FI) keyword heuristics (trt.50)**: match keywords as `\b<stem>` left-boundary prefixes (free suffix) so RU/FI inflection matches without mid-word noise ("провер"→проверьте, "tarkist"→tarkistaisitko; "etsi" can't fire inside "metsissä"). Avoid stems <4 chars and bare common verbs ("add"→"address", "hei"→"heitä", "list"→"listen"); keep dynamic-source keywords (task catalog) English per the entry contract and bridge to RU/FI via a scorer-owned translation map (`CATALOG_KEYWORD_TRANSLATIONS`).
- **Instrumented verdict degrade (trt.53)**: to rewrite a parsed `RouterDecision` (frozen dataclass) in the gate, stash the audit marker in `decision.raw` FIRST, then `dataclasses.replace(decision, ...)` — the raw dict is shared by reference, so the marker survives the replace and rides the existing `RouterDecisionMade` emit into `agent_decisions.raw_output` (the trt.50 ride-along). Place the degrade before BOTH the triage-timing emit (the row then carries the *effective* action) and the decision emit (the marker persists); rates become derivable with zero schema work.
- **Out-of-band failure re-entry seam (trt.53, until the Phase-5 queue)**: `TaskCoordinator.attach_failure_reporter` fires AFTER the terminal row update, only for `failed` settles (never done/cancelled); `RouterGate.__init__` auto-attaches its `report_task_failure` whenever built with `tasks=`, so every assembly (job_session, playground, test harnesses) gets the no-dead-promises wiring with zero extra steps. The correction is `say()` speech with NO terminal and NO AgentSpoke (trt.54's scope) — but `session.say()` adds it to the LiveKit chat ctx, so the router *quotes the walk-back on later turns* and starts declining honestly (emergent trt.55 preview; also the cleanest live proof the speech happened).
- **Proving say()-path speech live when api logs sit at WARNING (trt.53)**: per-turn TTS-row counts in `session_timings` vs the recorded utterance's sentence count (+1 row = the unrecorded say) + the session-detail activity log showing the extra TTS row's audio seconds starting at ack-end + grepping api logs for the *failure-leg* markers (0 hits across N settles = success path by elimination). The INFO success line stays pinned by unit tests, not docker logs.
- **Speech-kind + exact-turn stamping on AgentSpoke (trt.54)**: every spoken utterance emits `AgentSpoke(kind=..., turn_id=...)` — `kind ∈ reply|ack|status|correction`, `turn_id` resolved through the SAME shared `TurnIndex` as the decision/terminal events, both optional-with-defaults so legacy emitters (unified pipeline, old fixtures) parse unchanged. The subscriber stamps `final_text` by exact turn first (recency scan = legacy fallback only) and `kind="correction"` inserts an UNLINKED utterance row that stamps nothing — out-of-band speech reaches chat/history without ever clobbering a turn's canonical text. Don't pre-discard the reply-audio buffer for QUEUED out-of-band say() speech (the resolver fires while the ack still plays; the ack's own completion flush owns the buffer).
- **transcript_window on the decision event unlocks replay + the Heard step (trt.54)**: the agent-path `input_window` was `{"mode"}` only — the gate now passes a `transcript_window` (prior ctx capped, current utterance `is_current: true`, legacy entry shape) through `record_decision`, and the emitter merges it per turn. One change feeds THREE consumers: the timeline's "Heard you" on reload, `summarizeContext`, and `load_replay_fixture._heard_from_input_window` — agent sessions went from 0 replayable turns to full recorded↔replayed diffs. When adding decision-row context, reuse the legacy `transcript_window` key/shape rather than inventing a new one.
- **WS payload passthrough means event fields are free (trt.54)**: `app/api/ws.py::_build_envelope` flattens EVERY event payload key into the wire frame — new fields on a pipeline event (e.g. `kind`, `turn_id` on agent_spoke) reach the frontend with zero ws-layer changes; only the TS interface needs the optional fields. Live-view caveat fixed en route: `handleAgentSpoke` used to match `outcome === 'pending'`, but the terminal event always lands FIRST (same Redis channel) and flips the outcome, so the live finalText never applied — match by the event's `turn_id` instead.
- **Conditional timeline steps**: number `TurnStep.index` positionally after building the array (a conditional step — e.g. the delegate-only task step — would leave holes in hardcoded indices); gate "missing vs skipped" on the *effective* router action (`ack_fallback.to_action` when the degrade marker is present, else `raw_output.action`) so a say-path turn's absent answer-prompt reads "Skipped — no answer hop", not as a data gap.
- **Interrupted partials via a take-at-done caption buffer (trt.58)**: the gate owns a `SpeechCaptionBuffer` (observability.py) fed by a tee on the agent's `tts_node` interim sink (`build_agent_runtime` composes `gate.note_speech_caption` + forwarder; resets at `sequence==0`). EVERY speech done-callback starts with `partial = self._captions.take()` (take = read-and-clear) so no later speech can inherit stale text, and the start-of-speech hygiene points (`bind_reply`, `_say_with_terminal` pre-say) clear alongside `discard_reply()` — but NOT `report_task_failure` (queued behind a playing ack, same rationale as the audio buffer). Interrupted + partial non-empty → ledger terminal FIRST (unchanged `no_reply(barge_in)`, first-wins gates the spoke emit) then `record_spoke(partial, interrupted=True)` and DON'T discard the audio (the spoke emitter's `take_reply()` owns the flush, so the partial gets a WAV); interrupted + no captions → legacy discard-and-record-nothing. Subscriber: the `interrupted` divergence branch must come FIRST (before the ack/status bucket) → `override_actor="user"`; texts matching (1-sentence ack fully flushed) legitimately need no actor. UI derives "interrupted with partial" with NO new decision field: `no_reply_reason==='barge_in' && final_text` (`isInterruptedPartial`), and suppresses the redundant muted "No reply" row only for that case.
- **Driving a deterministic barge-in for browser validation (trt.58)**: voice-loop fake-mic barges race the local LLM's first-sentence latency (9 s gap → llama3.2:3b had flushed NOTHING; the turn correctly recorded no partial) — instead mute the mic, TYPE the long ask, and have an **in-page** `evaluate_script` poll click the session panel's Interrupt button once `[data-testid="bot-partial-line"]` has grown (zero MCP round-trip latency; the button drives the same `SpeechHandle.interrupted` path as voice barge-in). Also: the kept WAV on an interrupted utterance is the synthesized-ahead audio (96 s for ~20 s heard) — the caption TEXT is the operator-facing approximation, documented as such.

The same discipline applies to ANY stack-state capstone work: snapshot → swap → measure → restore-exactly, and keep the snapshot as a .validation artifact.
